# AGENTS.mdジェネレーター 初期リリース計画

## 結論

初期リリースでは、ソフトウェア開発者が質問に回答すると、プロジェクト固有の `AGENTS.md` 雛形を生成・コピー・ダウンロードできる静的Webアプリを提供する。

ブラウザ内だけで動作する `Vite + React + TypeScript` のSPAとして実装し、回答内容はサーバーへ送信せず、端末にも保存しない。ログイン、DB、外部AI API、広告、課金、解析SDKは初期リリースに含めない。公開先はCloudflare Pagesとし、GitHub連携による静的デプロイを行う。

## 目的

開発者がAIコーディングエージェントに渡す作業ルールを、毎回ゼロから考えたり、既存テンプレートを不要な項目ごと修正したりする負担を減らす。

技術スタック、検証コマンド、Git運用、禁止事項などを質問形式で整理し、すぐリポジトリに置けるMarkdownを生成する。

## 想定ユーザー

- AIコーディングエージェントを利用して個人開発または小規模チーム開発を行うソフトウェア開発者
- プロジェクトごとの作業ルールを `AGENTS.md` に明文化したい開発者
- テンプレートを複製して編集するより、必要な項目だけ入力して雛形を得たい人

## 解決したい課題

- `AGENTS.md` に何を書くべきか分からず、開始が遅くなる
- 技術スタック、テスト、Git運用などのルールが散在し、AIエージェントへの指示が一貫しない
- 汎用テンプレートには不要な項目や不足する項目があり、手編集に時間がかかる
- プロジェクト固有の禁止事項や検証コマンドを漏らしやすい

## 採用方針

### 提供形態

- Webアプリ: 採用。URLへアクセスしてすぐ使える静的SPAとする。
- PWA: 初期リリースでは見送る。オフラインインストールやプッシュ通知は主要価値に不要。
- モバイルアプリ: 見送る。入力・コピー・ダウンロードはモバイルブラウザで完結する。
- LINE Bot: 見送る。Markdownの確認とコピーに向かない。

### 技術スタック

採用:

- ビルド／開発環境: Vite
- UI: React
- 言語: TypeScript（strict設定）
- スタイル: Tailwind CSS。初期リリースではUIコンポーネントライブラリを追加しない。
- ユニット／UIテスト: Vitest と React Testing Library
- 静的ホスティング: Cloudflare Pages
- CI: GitHub Actions

理由:

- 質問フォーム、回答状態、生成結果のプレビューを扱うため、Reactの宣言的なUIと状態管理が必要十分。
- TypeScriptにより質問定義・回答・生成結果の対応漏れをコンパイル時に検出できる。
- Viteは静的SPAを素早く構築・buildでき、バックエンドを必要としない。
- Tailwind CSSなら余白、幅、ブレークポイント、フォーカス状態をコンポーネント単位で一貫して記述でき、フォーム中心のUIを素早く実装できる。
- Tailwind CSSはユーティリティCSSとして採用し、既製のUIコンポーネントライブラリは追加しない。必要な見た目とアクセシビリティはアプリ側で明示する。
- Cloudflare Pagesは静的成果物をGitHub連携で公開でき、サーバー実装や秘密情報を不要にする。
- GitHub Actionsでlint、型チェック、テスト、buildをPull Requestごとに確認できる。

見送るもの:

- Next.js / SSR: 動的レンダリングやサーバーAPIが初期リリースに不要。
- 外部AI API: 回答を決定的なテンプレートへ変換すれば初期リリースの価値を満たせる。APIキー、費用、送信データの取り扱いも不要になる。
- DB／BaaS: アカウント、共有、履歴機能を初期リリースに含めない。
- UIコンポーネントライブラリ: Tailwind CSSだけで初期リリースのUIを実装できるため、既製コンポーネントの依存とカスタマイズ負荷を避ける。
- 状態管理ライブラリ: フォームの局所状態はReact標準機能で扱える。

### データ管理

初期リリースでの保存方針:

- 回答値と生成結果はブラウザのメモリ内だけで保持する。
- 送信、永続化、同期は行わない。
- ページ再読み込みやタブを閉じた場合、回答値は消えることをUIで案内する。

保存しないもの:

- アカウント情報
- プロジェクト名、リポジトリURL、自由記述を含む入力内容
- 生成済み `AGENTS.md` の履歴
- 利用行動や識別子

将来検討:

- ユーザーが明示的に選んだ場合のみ使えるlocalStorageの下書き保存
- URL共有またはGitHub連携による共有
- テンプレートの保存・比較

### SEO / 公開方針

- Cloudflare PagesでHTTPS公開する。
- title、description、OGP、faviconを設定する。
- 公開前にトップページ、主要操作、直接アクセス、404を確認する。
- 初期公開では独自ドメインを必須にしない。PagesのURLで公開し、必要に応じて後から追加する。
- 静的ページとして検索エンジンに公開する。robots.txtとsitemapの設定は公開Issueで実装方式に合わせて確認する。

### 収益化

初期リリースでは収益化しない。

将来候補:

- 開発種別ごとの有料テンプレート
- チーム向け共有・管理機能
- スポンサー表示

初期リリースで入れないもの:

- 広告SDK
- 解析SDK
- 課金
- アフィリエイト
- メール収集

## 初期リリーススコープ

### 作る

- プロジェクト運用ルールを聞く質問フォーム
- 必須項目のバリデーションと修正案内
- 回答から `AGENTS.md` を組み立てる決定的な生成ロジック
- 生成Markdownのプレビュー
- クリップボードへのコピー
- `AGENTS.md` ファイルのダウンロード
- スマートフォンで完了できるレスポンシブUI
- 利用方法、入力データの扱い、生成結果の確認を案内する静的情報
- lint、型チェック、テスト、buildを確認するCI
- Cloudflare Pagesへの公開手順

### 作らない

- ログイン、ユーザー管理、権限管理
- DB、サーバー処理、クラウド保存
- 外部API連携、AI API呼び出し
- 既存リポジトリの自動解析
- GitHubリポジトリへの直接コミット
- 複数テンプレートの課金販売
- 多言語対応
- 管理画面、分析画面、利用ログ
- PWAのインストール、通知、オフラインキャッシュ

## 画面構成

### `/`

- アプリの目的と「作成をはじめる」導線
- 質問フォーム
- 入力不足時のエラー表示
- 生成結果プレビュー
- コピー／ダウンロード操作
- データの扱いと利用上の注意への導線

初期リリースでは複数ページ遷移を増やさず、1ページ内で次の流れを完結させる。

1. 利用目的を確認する
2. 質問へ回答する
3. 必須項目を検証する
4. `AGENTS.md` を生成してプレビューする
5. 必要なら質問へ戻って修正する
6. コピーまたは `AGENTS.md` をダウンロードする

## 入力項目

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| プロジェクト名 | はい | AGENTS.mdの対象プロジェクト名 |
| プロジェクトの目的 | はい | 解決する課題と提供する価値 |
| 提供形態 | はい | Web、モバイル、CLI、APIなど |
| 技術スタック | はい | 言語、フレームワーク、主要ライブラリ |
| ディレクトリ構成・主要ファイル | いいえ | エージェントが参照すべき構成 |
| 開発・検証コマンド | はい | install、dev、lint、typecheck、test、build |
| コーディング規約 | いいえ | 命名、フォーマット、型安全性など |
| テスト方針 | はい | テスト対象、実行タイミング、受け入れ基準 |
| Git／Issue／PR運用 | はい | ブランチ、コミット、レビュー、PRの方針 |
| AIエージェントの作業ルール | はい | 実装前確認、報告事項、禁止事項 |
| 追加の禁止事項・注意点 | いいえ | 秘密情報、外部サービス、スコープ制限など |
| ユーザーとのコミュニケーション方針 | いいえ | 言語、トーン、確認が必要な判断 |

質問の詳細なID、入力形式、選択肢、出力との対応はIssue #2で確定する。

## 出力項目

生成する `AGENTS.md` には、回答に応じて以下のセクションを含める。

1. プロジェクトの目的と対象
2. 技術スタックと構成
3. 開発・検証コマンド
4. 実装方針とコーディング規約
5. テスト・品質確認の方針
6. Issue、Git、PR運用
7. AIエージェントの作業開始前・実装後のチェックリスト
8. 禁止事項と安全上の制約
9. ユーザーへの報告・コミュニケーション方針

任意項目が未回答の場合は、空の見出しや「未定」の文言を出さず、該当セクションまたは箇条書きを省略する。

## 非機能要件

- スマートフォン幅320px程度からデスクトップ幅まで、入力・生成・コピー・ダウンロードを完了できる。
- キーボードのみで主要操作ができ、フォーカス位置、ラベル、エラー内容が分かる。
- 必須項目の不足時は、該当項目と修正方法を表示する。
- 不正な入力値、生成失敗、Clipboard API非対応時にアプリ全体がクラッシュしない。
- 入力内容をネットワーク送信しない。
- 生成結果は同じ回答に対して同じMarkdownを返す。
- 公開前にlint、型チェック、テスト、buildがすべて成功する。
- 秘密情報、個人情報、外部サービスの認証情報をリポジトリへ含めない。

## 将来の拡張余地

- フレームワーク・言語・デプロイ先ごとのテンプレート
- localStorageを用いた任意の下書き保存
- 既存 `AGENTS.md` の読み込みと差分表示
- GitHub連携による作成先リポジトリへのPull Request作成
- チーム共有、テンプレート管理、課金機能
- 多言語の質問・出力

これらは初期リリースの実装・公開を遅らせないため、別Issueとして明示的に採用するまで実装しない。
