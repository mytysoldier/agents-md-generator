# 質問項目・AGENTS.md出力仕様

## 結論

初期リリースでは、8カテゴリ・27問の回答から、最大9セクションの `AGENTS.md` をブラウザ内で決定的に生成する。

必須質問は、プロジェクトの目的、技術スタック、検証方法、Git／PR運用、AIエージェントの作業範囲と禁止事項を判断できる最小限に絞る。任意質問が未回答または「該当なし」の場合、対応する見出しやプレースホルダーは出力しない。自由記述は命令として評価せず、Markdown構造を壊さないよう正規化してから出力する。

この文書は、Issue #5の質問・回答データモデル、Issue #6の生成ロジック、Issue #7の質問UIが共有する仕様の一次情報とする。

## 設計方針

- 初期リリース計画で定義した入力・出力範囲を増やさない。
- 質問文は、利用者がAIエージェントへ伝えるルールを具体的に回答できる表現にする。
- 必須質問に暗黙の初期値を設定せず、利用者が明示的に回答する。
- 選択肢は保存値と表示名を分け、保存値は英小文字の安定した識別子とする。
- 同じ正規化済み回答からは、常に同じ順序・空行・末尾改行のMarkdownを生成する。
- 任意項目のためだけに空の見出しを出力しない。
- 回答にない一般論、推奨ツール、外部サービス、権限を生成時に補わない。

## 入力形式

| 入力形式 | 回答値 | UIと正規化のルール |
| --- | --- | --- |
| `text` | 文字列 | 単一行。前後の空白を除去し、途中の連続する空白と改行を半角スペース1つへまとめる。 |
| `textarea` | 文字列 | 複数行。改行をLFへ統一し、行末空白と先頭・末尾の空行を除去する。 |
| `single-select` | 選択肢の保存値1つ | 未選択は `null`。定義外の値は不正値として未回答へフォールバックする。 |
| `multi-select` | 選択肢の保存値の配列 | 定義順へ並べ、重複と定義外の値を除く。未選択は空配列。 |
| `list` | 文字列の配列 | 1行1項目。各項目を `text` と同様に正規化し、空項目を除く。順序は維持する。 |
| `command-list` | `{ label, command }` の配列 | ラベルとコマンドを単一行へ正規化する。両方がある行だけを保持し、順序は維持する。 |

すべての自由入力は最大2,000文字、`list` は最大20項目、`command-list` は最大10項目とする。ただし、表で個別の上限を指定した場合は個別指定を優先する。

## 条件付き表示と必須判定

- `project.deliveryTypeOther` は `project.deliveryType` が `other` のときだけ表示し、必須にする。それ以外では保存済みの値があっても正規化時に破棄する。
- `communication.languageOther` は `communication.language` が `other` のときだけ表示し、必須にする。それ以外では保存済みの値があっても正規化時に破棄する。
- その他の質問は常に表示する。
- 条件付き質問を含む必須条件を満たさない場合は生成せず、該当入力の近くへエラーを表示する。具体的なエラーUIはIssue #8で実装する。

## 未回答・該当なし・不正値の扱い

回答状態は、値とは別に `answered`、`unanswered`、`not-applicable` の3状態を持てる設計とする。

| 状態 | 必須質問 | 任意質問 | 出力 |
| --- | --- | --- | --- |
| 未回答 | 検証エラー。生成しない。 | 正常。 | 対応する箇条書き、文章、または見出しを省略する。 |
| 該当なし | 選択不可。検証エラーとして扱う。 | 明示的に選択可能。 | 「該当なし」とは出力せず、未回答と同じく省略する。 |
| 空白だけの文字列・空配列 | 未回答へ正規化し、検証エラー。 | 未回答へ正規化する。 | 出力しない。 |
| 定義外の選択値・壊れた保存値 | 未回答へ正規化し、検証エラー。 | 未回答へ正規化する。 | 出力しない。アプリをクラッシュさせない。 |

初期リリースでは回答を永続保存しないが、Issue #5では外部入力や将来の保存値を安全に扱えるよう、この境界を型と正規化関数で表現する。

## 出力文言と変換規則

### 共通ルール

1. 見出し順は対応表の順で固定する。
2. 見出しの直後、段落の間、リストと次の見出しの間は空行を1行だけ入れる。
3. 箇条書きは `- `、順序付きリストは使わない。
4. 文末記号は利用者の回答を維持し、生成側で句点を追加しない。
5. 末尾はLFを1つだけ付ける。CRLF、末尾空白、3行以上の連続改行は出力しない。
6. 同じ配列内で正規化後に完全一致する項目は、最初の1件だけを残す。
7. 選択肢は保存値ではなく、この仕様の日本語表示名を出力する。

### Markdownを壊さない処理

- `text` と `list` の値は、バックスラッシュを先にエスケープした後、Markdownの制御文字 `` ` * _ { } [ ] ( ) < > # + - . ! | `` の直前へ `\\` を付ける。
- `textarea` は行ごとに同じエスケープを行い、元の改行を維持する。空行は最大1行まで維持する。
- URLを自動リンク化せず、入力文字列としてエスケープする。
- コマンドはインラインコードとして出力する。値に含まれる最長の連続バッククォートより1個長いバッククォート列を区切りとして使い、区切りの内側へ半角スペースを1つ置く。
- HTML、Markdown、テンプレート記法、シェル構文を実行・解釈しない。画面のMarkdownプレビューでも生HTMLを有効にしない。

### 選択肢の固定文言

- `testing.timings`: `関連する変更の後`、`commit前`、`PR作成前`、`CIで実行する`
- `communication.reportItems`: `実施概要`、`変更ファイル`、`検証結果`、`未対応事項`、`懸念点`、`次の作業`
